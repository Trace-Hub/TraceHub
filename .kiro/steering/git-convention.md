# Git 컨벤션

커밋 및 브랜치 작업 시 반드시 아래 규칙을 따라야 합니다.

## 브랜치 네이밍

```
#<이슈번호>-<타입>-<설명>
```

예시:

- `#7-feat-components`
- `#12-fix-button-style`
- `#3-chore-setup-eslint`

## 커밋 메시지 템플릿

#[[file:.github/.gitmessage.txt]]

## 커밋 메시지 규칙

형식:

```
<타입>(<범위>): <제목>

<본문> (선택 사항, 한 줄 띄우고 작성. 72자 이내로 줄 바꿈)

Resolves: #<이슈번호>
See also: None
```

### 타입 목록

| 타입     | 설명                                            |
| -------- | ----------------------------------------------- |
| feat     | 새로운 기능 추가                                |
| fix      | 버그 수정                                       |
| docs     | 문서 수정                                       |
| style    | 코드 포맷팅, 세미콜론 누락, 코드 변경 없는 경우 |
| refactor | 코드 리팩토링                                   |
| test     | 테스트 코드 추가/수정                           |
| chore    | 빌드 관련 수정, 패키지 매니저 설정 등           |

### 범위(scope) 목록

| 범위    | 설명               |
| ------- | ------------------ |
| config  | 환경 구성          |
| domain  | 도메인 영역        |
| admin   | 관리자 영역        |
| user    | 사용자 영역        |
| product | 상품 영역          |
| api     | REST API 문서      |
| wiki    | Wiki 문서          |
| project | 프로젝트 전반 설정 |

### 규칙

- 제목은 40자 이내
- 본문은 선택 사항이며 한 줄 띄우고 작성, 72자 이내로 줄 바꿈
- `Resolves`: 해결한 이슈 번호
- `See also`: 관련된 이슈 번호 (없으면 None)
- 제목 끝에 마침표 금지
